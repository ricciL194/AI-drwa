# AI-drwa 漫剧制作工作区

本项目公开仓库保存漫剧制作规则、五份提示词模板、项目 Skill、检查脚本和可移植说明。连载正文、改编稿、分镜、生成提示词、资产图片、视频输入包、样片和成片属于本机制作档案，不进入公开 GitHub 版本。

## 首个公开版本说明

本仓库按“制作中的可移植工作区”公开，当前不是已完成的成片项目。剧本、分镜、提示词、资产和审核记录会持续更新；README 与连载目录中的“待制作”“待审核”“待补齐”状态是真实进度。

默认许可见 [LICENSE](LICENSE)：项目原创文字、规范、提示词、脚本和文档按 CC BY-NC 4.0 分享。生成图片、视频、音频、字体和其他第三方材料可能受单独的服务条款或权利限制，不能仅凭仓库许可推断为可商用。

生成记录中的 `source` 若为空，表示原始工具缓存位于创建这份记录的本机、未随仓库保存；继续工作应使用同一记录中的项目内 `dest` 和 `refs` 文件，不依赖本机缓存路径。

## 新电脑开始使用

1. 克隆仓库，打开项目根目录。公开版本只包含工作流与规范；若要继续某部作品，还需要把本机保存的 `连载/` 制作档案放回项目根目录。
2. 让 Agent 完整读取 [AGENTS.md](AGENTS.md) 和 [漫剧制作 Skill](.agents/skills/manju-production/SKILL.md)，再按任务读取 [制作规范入口](制作规范/README.md) 中对应的执行版与原始模板。
3. 若本机已有制作档案，再读取目标连载 README、当前采用稿、视觉规范和相关资产设定。例如 [极寒纪元](连载/极寒纪元/README.md)。审核状态以这些文件为准。
4. 使用 Python 3.9 或更新版本运行移植检查：`python3 工作流/scripts/check_project.py`。Windows 可使用 `py -3 工作流/scripts/check_project.py`。
5. 提出具体任务，例如“按项目规范审计《极寒纪元》第03集输入包”。检查单集结构：`python3 工作流/scripts/check_project.py --episode 连载/极寒纪元/改编/第03集`。

不自动读取 AGENTS.md 或不自动发现项目 Skill 的客户端，可以直接复制以下启动指令：

> 项目根目录是当前工作区。先完整读取 AGENTS.md、.agents/skills/manju-production/SKILL.md，按任务读取制作规范/README.md、对应执行版和原始模板，再读取目标连载 README 与已确认设定。只执行我指定的阶段；将产出、采用版本、审核状态和进度按项目约定写回文件。现在执行：〔具体任务〕。

## 工作流与移植

- [移植与发布说明](工作流/移植说明.md)：Git 保存范围、路径约定、工具需求、迁移验收和当前缺口。
- [制作规范](制作规范/README.md)：五模板的权威内容与冲突处理。
- [.agents/skills/manju-production/SKILL.md](.agents/skills/manju-production/SKILL.md)：任务路由和交付步骤；直接引用既有规范，不复制模板正文。
- [检查脚本](工作流/scripts/check_project.py)：只读检查入口、项目内文件依赖与单集结构。

阅读规范和编写文本只需要能访问项目文件的 Agent；实际出图、生成视频、配音仍需要新电脑可用的工具和账户。工具缺失时交付对应文稿并明确待制作项，不伪报生成完成。

公开仓库不会包含 `连载/` 目录。需要审计或继续制作时，将私有制作档案放回项目根目录，再运行对应的单集检查命令。若只使用公开工作流，根目录检查仍可验证规则、模板和脚本入口。

当前仓库尚未关联 GitHub 地址。创建远端后再设置 origin 并推送；不要将文档中的示例当作真实仓库地址。
