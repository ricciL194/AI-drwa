# 移植与发布说明

目标：新电脑克隆完整仓库后，不读取原聊天或原电脑的全局 Skill，就能按五模板继续执行指定任务。

## 保存范围与 Git

公开 GitHub 版本只保存规则、原始模板、执行版、Skill、检查脚本和迁移说明。正文、改编稿、分镜脚本、生成提示词、资产设定、图片、视频输入包、样片、成片和生成记录属于本机制作档案，统一保留在 `连载/`，由 `.gitignore` 排除，不进入公开仓库。完整制作档案仍在本机保留；公开仓库不再宣称克隆即可恢复全部成片制作资料。

`.gitignore` 还排除整个 `连载/` 制作档案及常见图片、视频、音频格式。空目录不会随 Git 保存，Agent 应按实际任务创建目录，不以空目录判断制作完成。

本次先建立本地 Git 仓库和可移植入口；GitHub 远端、首次提交及推送在确定目标仓库后进行。上传前检查将提交的文件范围，确保包含需要继续工作的素材。

## 路径与历史记录

- Markdown 链接相对于文档所在目录；任务 JSON 的 `dest`、`refs` 相对于项目根目录。
- 实际调用工具时，由 Agent/调用程序将项目相对路径解析为当前机器绝对路径，不将解析结果写回通用配置。
- 历史生成记录的 `source` 仅作原工具缓存溯源；公开版本中已清理本机绝对路径并置为空。它不随仓库复制，也不用于继续生成。应读取已归档的 `dest` 文件。历史嵌入提示词保持当时语义，不视作新的制作任务。
- 样片 concat 清单使用相对于清单所在目录的文件路径。样片制作脚本需要 Bash 与 FFmpeg；规范阅读、文稿创作和结构审计不依赖 FFmpeg。
- 音色 ID、视频模型及参考图绑定由实际工具确定，现存“待定”项保持待定。账户凭据配置在本机，不写入仓库。

## Agent 的加载方式

项目内 Skill 路径为 `.agents/skills/manju-production/SKILL.md`，根 AGENTS.md 直接指向它。客户端若不自动发现 Skill，使用根 README 的启动指令手动加载。未来自己的 Agent 启动程序应主动读取该入口，再按任务加载对应模板；不能仅把文件放在磁盘上就假定模型已读取。

文本制作没有额外第三方依赖。结构审计需要 Python 3.9+，只使用标准库。实际出图、视频和配音需要工具与账户；当前项目没有固定的自动生成服务，因此本次不引入虚构配置或 API。

## 移植验收

在另一目录或另一电脑打开完整项目，执行：

```sh
python3 工作流/scripts/check_project.py
python3 工作流/scripts/check_project.py --episode 连载/极寒纪元/改编/第01集
python3 工作流/scripts/check_project.py --episode 连载/极寒纪元/改编/第02集
python3 工作流/scripts/check_project.py --episode 连载/极寒纪元/改编/第03集
```

第一个命令检查工作流入口、模板和 JSON 中的归档文件/参考图。单集命令还检查分镜表中的镜头、提示词覆盖、资产登记与同名 PNG、生成节首尾帧、输入包提示词同步和 15 秒上限。退出码 0 表示检查范围内结构通过，1 表示有待修正项，不能解释为画面审核或创作质量通过。

再让没有历史对话的 Agent 仅凭仓库执行“审计第03集”：它应找到五模板入口，识别缺少首尾帧的生成节，保持待补齐状态，而不是直接宣布可生成。实际跨电脑与模型行为验收须在新环境完成；本机换目录检查只能验证路径独立性。

## 本次发现的既有差异

- 第03集已经绑定主素材，但 B 级首尾帧仍缺失，尚不能标记为结构齐备。
- 原审计文档中的“每节一个 EPXX_BXXX 目录”与现有整集输入包存在差异；统一使用 `EPXX_整集输入/`，按 B 编号索引首尾帧。
- 第01集的5张历史参考图已按生成记录从原始缓存恢复到公共资产目录，原始版本与现行推荐版本各自保留；所有 JSON `dest`、`refs` 检查通过。未来继续生成无需原缓存。
- 第01集输入包提示词包含后续运镜及结束状态修订，与改编目录提示词存在实质差异。当前检查会报告不同步；需在后续第01集修订任务中确认采用内容并统一回写。本次移植工作不替用户选择创作版本。

本文件记录移植机制；各集最新制作状态仍由连载 README、资产清单和审计记录维护。
